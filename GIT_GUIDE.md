# Инструкция: Как работать с проектом через GitHub

Эта инструкция поможет вам и вашему партнеру работать над кодом одновременно, не удаляя изменения друг друга и сохраняя историю проекта.

---

## 1. Как начать работу (Pull)
Каждый раз, когда вы садитесь за код, **первое**, что нужно сделать — это забрать последние изменения от партнера.

```bash
git pull origin main
```
*Что это делает: Синхронизирует вашу локальную папку с тем, что сейчас на Гитхабе.*

---

## 2. Как работать одновременно (Ветки / Branches)
Чтобы не мешать друг другу, лучше работать в отдельных «ветках». Представьте, что это параллельные реальности проекта.

### Как создать свою ветку:
Если вы планируете новую доработку (например, «фикс слайдера»):
```bash
git checkout -b feature/strategy-audit-v2
```

### Если партнер тоже что-то делает:
Он создаст свою ветку: `git checkout -b feature/partner-updates`. Вы сможете работать одновременно, и ваши файлы не будут перемешиваться до тех пор, пока вы не решите их объединить.

---

## 3. Как сохранить и отправить изменения (Commit & Push)
Когда вы закончили работу над задачей:

1. **Посмотрите, что изменилось:**
   ```bash
   git status
   ```

2. **Добавьте файлы в «пакет» для отправки:**
   ```bash
   git add .
   ```

3. **Запечатайте пакет комментарием:**
   ```bash
   git commit -m "Исправил слайдер и обновил единицы измерения"
   ```

4. **Отправьте на Гитхаб:**
   ```bash
   git push origin feature/strategy-audit-v2
   ```
   *Теперь ваша новая версия на Гитхабе, но старая в ветке `main` осталась нетронутой!*

---

## 4. Как объединить изменения (Merge)
Когда вы проверили, что всё работает в вашей ветке, и хотите перенести это в основной проект (`main`):

1. Перейдите в основную ветку: `git checkout main`
2. Обновите её: `git pull origin main`
3. Влейте свои изменения: `git merge feature/strategy-audit-v2`
4. Отправьте итоговый результат: `git push origin main`

---

## 5. Если возник «Конфликт» (Merge Conflict)
Это бывает, когда вы и партнер изменили **одну и ту же строчку** в одном файле.
- Git скажет: "Automatic merge failed".
- Вам нужно будет открыть этот файл. Вы увидите такие метки:
  ```
  <<<<<<< HEAD
  Ваш вариант текста
  =======
  Вариант партнера
  >>>>>>> feature/something
  ```
- Просто удалите лишние метки и оставьте тот вариант текста (или оба), который правильный. После этого сделайте `git add` и `git commit`.

> [!TIP]
> **Золотое правило:** Делайте `git pull` как можно чаще. Чем чаще вы синхронизируетесь, тем меньше шансов получить сложный конфликт.
